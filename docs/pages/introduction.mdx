# Zuplo Weather Gateway

This service provides two weather-focused endpoints:

- GET /weather/
- POST /weather/reset

The API reference page is generated from the OpenAPI file and remains the source of truth for route
shape and examples.

## GET /weather/

Resolves coordinates, calls OpenWeather, and returns a transformed response.

### Query Parameters

- latlon: Comma-separated coordinates, for example 32.46564,12.8737874
- player: Player ID resolved from the bundled player-location dataset
- com.broadsign.suite.bsp.resource_id: Alias for player
- debug: true or false. When true, adds a debug object to the response.
- filter: false disables response filtering and returns the full upstream payload.
- format: json returns JSON. Default response is JavaScript in the form `data = {...};`.

### Behavior Notes

- One of latlon, player, or com.broadsign.suite.bsp.resource_id is required.
- Latitude and longitude are normalized to 3 decimal places before upstream request.
- Response filtering is enabled by default.
- timestamp is always included.
- debug visibility is controlled only by debug=true.
- When debug=true, debug.original contains the upstream URL with appid masked.

### Common Errors

- 400 for missing or invalid query parameters.
- 404 when player or resource_id cannot be resolved.

## POST /weather/reset

Invalidates weather cache namespace by bumping the internal cache version key.

- Method: POST
- Path: /weather/reset
- Success response: 200

## Local Testing Examples

```bash
# Default JavaScript response with filter enabled
GET /weather/?latlon=32.46564,12.8737874

# Raw JSON response
GET /weather/?latlon=32.46564,12.8737874&format=json

# Return full upstream payload (filter disabled)
GET /weather/?latlon=32.46564,12.8737874&filter=false&format=json

# Include debug metadata
GET /weather/?player=YOUR_PLAYER_ID&debug=true&format=json

# Reset cache
POST /weather/reset
```

# Dynode Gateway

Edge API on Zuplo for **weather** (OpenWeather) and **Norway flights**
(Avinor), resolved from country player datasets or explicit query parameters.

The [API Reference](/api) is generated from `config/routes.oas.json` and is the
source of truth for parameter schemas.

**Live gateway:** `https://dynode-main-8eca196.zuplo.app`

## Endpoints

### Weather

| Method | Path | Player dataset | Cache TTL |
| --- | --- | --- | --- |
| GET | `/weather/sweden` | Sweden + shared test | 1 hour |
| POST | `/weather/sweden/reset` | — | Invalidate cache |
| GET | `/weather/norway` | Norway + shared test | 1 hour |
| POST | `/weather/norway/reset` | — | Invalidate cache |
| GET | `/weather/poland` | Poland + shared test | 1 hour |
| POST | `/weather/poland/reset` | — | Invalidate cache |

Requires `OPENWEATHER_API_KEY` in the Zuplo environment (or local `.env`).

### Flights

| Method | Path | Notes | Cache TTL |
| --- | --- | --- | --- |
| GET | `/flights/norway` | Avinor XmlFeed, gate filter | 180 seconds |
| POST | `/flights/norway/reset` | — | Invalidate cache |

No Avinor API key. Attribution is included in responses.

## Player datasets

Country files under `modules/players/`:

| File | Routes | Notes |
| --- | --- | --- |
| `sweden.ts` | `/weather/sweden` | Weather coordinates only |
| `norway.ts` | `/weather/norway`, `/flights/norway` | Weather + gate/IATA for flights |
| `poland.ts` | `/weather/poland` | Weather coordinates only |
| `test.ts` | All country routes | Demo/QA players merged into every lookup |

Norway flight players are maintained from `modules/players/NorwayPlayers.csv`
via `scripts/update-norway-from-csv.mjs`.

### Player id query aliases

All weather and flights routes accept:

- `player`
- `resource_id`
- `com.broadsign.suite.bsp.resource_id` (legacy CMS contract)

### Optional player fields (flights)

- `Gate` — one gate, several gates (comma-separated or dot notation), or `*` for all gates at the airport
- `IATA` — airport code (e.g. `OSL`, `BGO`, `TRD`)

Demo/QA player IDs (available on every country endpoint):

| Player ID | Gates | IATA |
| --- | --- | --- |
| `759244535` | D9 | OSL |
| `582309742` | D1 | OSL |

## Weather

Resolve location from **`latlon`** or a **player id** (one is required).

| Parameter | Description |
| --- | --- |
| `latlon` | Comma-separated latitude,longitude (rounded to 3 decimals before upstream call) |
| `player` / `resource_id` | Resolved from the country-specific player dataset |
| `format=json` | Raw JSON instead of default JavaScript `data = {...};` |
| `filter=false` | Return full OpenWeather payload instead of the default field allowlist |
| `debug=true` | Include masked upstream URL and matched player metadata |

Default filtered weather fields: `coord`, `main.temp`, `weather[0].main`,
`wind.speed`, `rain.1h`.

## Flights (Norway)

Two lookup modes — **never combine them**:

1. **Direct** — `gates` with optional `iata`, or `iata` alone for all gates at that airport
2. **Player** — `player` or `resource_id` (resolves gates + IATA from the Norway dataset)

| Parameter | Description |
| --- | --- |
| `gates` | Gate code, comma-separated list, dot notation (`C2.C3`), or `*` for all gates. Legacy alias: `gate`. |
| `iata` | Airport code. With `gates`, defaults to `OSL` when omitted. Without `gates`, returns all gates at this airport. Alias: `airport`. |
| `player` / `resource_id` | Player lookup from Norway (+ test) dataset |
| `direction` | `AD` both (default), `A` arrivals, or `D` departures |
| `format=json` | Raw JSON instead of default JavaScript |
| `filter=false` | Return full payload instead of the default field allowlist |
| `debug=true` | Include upstream Avinor URL and feed metadata |

Default filtered flights fields: `iata`, `airportCode`, `direction`, `gates`,
`flights`, `attribution`.

Each flight may include `airportName` (from Avinor airport names). **Departures**
match gate filters more reliably than arrivals.

## Common response behaviour

- Default body: JavaScript `data = {...};`
- `format=json` for raw JSON
- `filter=false` bypasses the endpoint field allowlist
- `debug=true` adds upstream/debug metadata
- `timestamp` is present on flights success payloads
- Weather errors are plain text; flights errors use structured JSON when `format=json`

## Sample signage client

The **1080×1920** portrait board is linked from this portal at
`/samples/v1/index.html` (source: `samples/v1/` and `docs/public/samples/v1/`).

It loads flight data from the live gateway, forwarding query parameters from the
page URL:

- Player lookup: `player` or `resource_id`
- Direct lookup: `gates` and optional `iata`, or `iata` alone for all gates
- Optional: `direction` (`AD` default), `refresh` (seconds), `api` (gateway base URL override)

Example:

```text
/samples/v1/index.html?resource_id=759244535&direction=D
/samples/v1/index.html?gates=D9&iata=OSL&direction=D
```

```bash
GET /weather/sweden?player=582607705&format=json
GET /weather/norway?player=582309742&format=json
GET /weather/poland?player=963988113&format=json
GET /flights/norway?player=582309742&format=json
GET /flights/norway?gates=D9&iata=OSL&direction=D&format=json
GET /flights/norway?gates=C34,C35&iata=BGO&format=json
GET /flights/norway?iata=BGO&format=json
POST /weather/norway/reset
POST /flights/norway/reset
```
